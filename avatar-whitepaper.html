What this document defines

The portable avatar record and the rules used to resolve it. Commerce, blockchain custody, authentication, and game-state storage are integrations—not requirements of the core schema.

02 · Control and loadout

Marketplace → Backpack → Equip → Enter World.

  1. AcquireBuy, claim, mint, or receive
  2. BackpackStore a reference to Avatar ID
  3. DesignateSelect one active avatar
  4. EquipValidate slots and fit profile
  5. SpawnVerify, load, attach, apply

Backpack references, never duplicates

An inventory entry records the asset ID, acquisition state, and listing lock. The canonical service resolves current media, traits, and compatibility. Transfers change the controller without moving large model data.

Active avatar is a session choice

Before spawn, a trusted service authenticates the player; authorizes control and world access; checks approval status; resolves pinned media; validates the loadout; calculates effective stats; and signs a short-lived, non-transferable session snapshot.

Compatibility rule: each item declares a fit profile such as humanoid-small or black-sheep-rig@1, allowed slots, attachment bone, offsets, and conflict groups.

Control is not assumed to mean blockchain ownership.

ownerId identifies the authoritative account in this schema. A token ID is optional provenance metadata. When an on-chain collection is used, the server must verify chain, contract, token, and current controller before granting a session.

04 · Interoperability

A strict creator standard makes an open world possible.

Asset validation

glTF 2.0 / GLB, optional USDZ, declared byte and geometry budgets, PBR textures, HTTPS or same-origin URLs, collision bounds, units in meters, origin, scale, and spawn clearance.

Rig validation

Versioned rig profile, attachment bones, skin weights, humanoid or custom classification, neutral pose, root motion policy, and retargeting map.

Animation contract

Supported semantic action names include: idle, walk, run, jump, turn, interact, dance, emote, use_tool, damage, and defeat.

Trust and rights

Creator identity, rights declaration, malware and unsafe-content scans, moderation state, SHA-256 content digest, version history, and a revocation path for compromised files.

02 · Control and loadout

Marketplace → Backpack → Equip → Enter World.

  1. AcquireBuy, claim, mint, or receive
  2. BackpackStore a reference to Avatar ID
  3. DesignateSelect one active avatar
  4. EquipValidate slots and fit profile
  5. SpawnVerify, load, attach, apply

Backpack references, never duplicates

An inventory entry records the asset ID, acquisition state, and listing lock. The canonical service resolves current media, traits, and compatibility. Transfers change the controller without moving large model data.

Active avatar is a session choice

Before spawn, the world verifies control, world access, and moderation status; resolves the versioned GLB and animations; validates equipped items; calculates effective stats; then issues a short-lived session snapshot.

04 · Interoperability

A strict creator standard makes an open world possible.

Asset validation

glTF 2.0 / GLB, optional USDZ, file-size and polygon budgets, PBR textures, safe URLs, collision bounds, origin, scale, and spawn clearance.

Rig validation

Versioned rig profile, attachment bones, skin weights, humanoid or custom classification, neutral pose, root motion policy, and retargeting map.

Animation contract

Required semantic actions: idle, walk, run, jump, turn, interact, dance, emote, use_tool, damage, and defeat.

Trust and rights

Creator identity, IP declaration, unsafe-content scan, moderation state, provenance hash, version history, and a revocation path for compromised files.

Submitted→Automated checks→Human review→Market Approved→Published
